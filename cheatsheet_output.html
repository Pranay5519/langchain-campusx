LangChain Components Cheat Sheet

01

Core LangChain Primitives

Models

LLMs: Large Language Models for text generation.
Chat Models: Optimized for conversational interfaces, handle message lists.
Vision Models: Multimodal models capable of processing image inputs.
Hugging Face Open Source Models: Integration with models from the Hugging Face ecosystem.
Embedding Models: Convert text into numerical vector representations for similarity search.

Prompts

Static Prompts: Fixed string of text, no variables.
Dynamic Prompts: Utilizes templates with placeholders for variable insertion.
Single Message: A basic prompt as a simple string.
List of Messages: Structured input for chat models (e.g., Human, System, AI messages).
Prompt Template: General template for LLMs, supporting string formatting.
Chat Prompt Template: Specific template for chat models, managing roles and message types.
Message Placeholder: Variables within a template, e.g., `{query}`.
Human Message: Input from the user.
System Message: Sets the context or persona for the AI.
AI Message: Response from the AI model.
EXAMPLE A Chat Prompt Template for a helpful assistant: 
ChatPromptTemplate.from_messages([
    ("system", "You are a helpful AI assistant."),
    ("human", "{user_query}")
])

Chains

Sequential Chain: Executes steps in a predefined order, passing output from one to the next.
Parallel Chain: Runs multiple components concurrently and combines their outputs.
Conditional Chain: Implements branching logic, executing different paths based on conditions.

Runnables (LangChain Expression Language - LCEL)

Task-specific Runnables: Pre-built, optimized components for common tasks.
Runnable Primitives: Basic, composable units like LLMs, PromptTemplates, OutputParsers.
Runnable Parallel: Combines multiple runnables to execute in parallel (e.g., `RunnableParallel({"output1": runnable1, "output2": runnable2})`).
Runnable Sequence: Chains runnables together in a linear flow (e.g., `prompt | llm | parser`).
Runnable Passthrough: Passes the input directly to the next runnable, useful for adding keys to context.
Runnable Branch: Allows conditional execution of different runnables based on input.
Runnable Lambda: Wraps a Python function to make it a runnable component.

Tools

Built-in Tools: Pre-defined functionalities like web search, calculators, or access to specific APIs.
Custom Tools: User-defined functions wrapped to be callable by an agent or chain.
02

Data Handling & Retrieval

Document Loaders

Text Loader: Loads raw text content from files.
PDF Loader: Extracts text from PDF documents.
Web Based Loader: Fetches and parses content from URLs (e.g., `WebBaseLoader`).
CSV Loader: Reads data from Comma Separated Values files.
Integration with Vector Stores: Loaders prepare data for storage in vector databases.

Text Splitters

Recursive Character Text Splitter: Splits by a list of characters, attempting to keep paragraphs/sentences together.
Semantic Text Splitter: Advanced splitting that aims to preserve semantic meaning within chunks.
Length Based Splitting: Simple splitting based on a maximum character or token count.
Chunking: The general process of dividing large documents into smaller, manageable pieces.
Chunk Size: The maximum length of each split document chunk.
Chunk Overlap: The number of characters/tokens shared between consecutive chunks to maintain context.

Retrievers

Web Retriever: Retrieves information from the web based on a query (e.g., `WebSearchRetriever`).
Similarity Retriever: Basic retriever that finds documents most similar to a query based on embeddings.
Multi Query Retriever: Generates multiple variations of a user query to improve retrieval coverage.
MMR (Maximal Marginal Relevance): Selects documents that are both relevant to the query and diverse among themselves.
Contextual Compression Retriever: Reduces the size of retrieved documents to fit within the LLM's context window.
03

Structured Output & RAG

Structured Output & Output Parsers

Structured Output: Guiding LLMs to generate responses in specific formats (e.g., JSON, Pydantic objects).
Pydantic Output Parser: Parses LLM output into a Python Pydantic model instance, providing validation.
JSON Output Parser: Parses LLM output into a standard JSON object.
String Output Parser: The default parser, simply returns the LLM's raw string output.
Pydantic Models: Python classes defining the desired data schema for output.
Nested Pydantic Models: Allows for complex, hierarchical data structures in the output.
List of Models: Enables parsing output into a list of Pydantic model instances.
LLM Support: Not all LLMs inherently support structured output; some require specific prompting or fine-tuning.
EXAMPLE Defining a Pydantic model for structured output: 
from pydantic import BaseModel, Field

class Joke(BaseModel):
    setup: str = Field(description="the setup of the joke")
    punchline: str = Field(description="the punchline of the joke")

RAG (Retrieval Augmented Generation) Workflow

A step-by-step process for enhancing LLM responses with external, relevant information.

1. Load Data (e.g., PDF, Text, Web)
→
2. Split Data (into smaller chunks)
→
3. Embed Chunks (to vector representations)
→
4. Store in Vector Store (for efficient search)
→
5. User Query
→
6. Retrieve Relevant Chunks (from Vector Store)
→
7. Augment Prompt (Query + Retrieved Context)
→
8. Generate Response (using LLM)
RAG Purpose RAG combines the strengths of large language models (LLMs) with external knowledge bases. It allows LLMs to access up-to-date, factual information beyond their training data, reducing hallucinations and improving accuracy.
